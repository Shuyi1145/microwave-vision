# 并行开发计划与Goal验收
总目标：在已可离线运行的安卓首版上，提高中文教学界面与操作体验，形成能独立提交、可回归、便于参赛展示的版本。先保证完赛，再扩充功能；不追求同时替换整站技术栈。

## 已完成的共同基线
现有React/Vite工程、6门实验课程、KaTeX、物理模型、热力图、诊断练习、本地记录和Capacitor安卓首版。原有21项公式测试通过；安卓11/15模拟器已完成不同范围验证，实体手机未全面验证。当前APK不支持远程更新。
本次协作基础已创建：固定接口、独立预览、文件越界检查、GitHub质量工作流、三份详细任务提示词。功能模块尚未开发，Skill安装不等于设计完成，GitHub推送不等于CI通过。

## 可以立即并行的任务
W1 WorkBuddy门户：workbuddy/portal-ui；只改src/features/portal、docs/reports/portal。Goal：封面、工作台、选课页更有微波学习辨识度。DoD：三种view独立预览；四模块/六课程正确；手机无溢出；封面一个入口；浅色中文；键盘可用；减弱动效；构建测试通过。详细见WORKBUDDY-PORTAL.md。
W2 WorkBuddy课程面板：workbuddy/lesson-ui；只改src/features/lesson-ui、docs/reports/lesson-ui。Goal：手机上图形观察与参数操作不用来回长滚动。DoD：纯展示槽组件；参数抽屉/面板可展开关闭；可放入真实图形而不截断；桌面/手机可用；播放回调受控；不重算物理；关闭/焦点合理；独立预览通过。详细见WORKBUDDY-LESSON.md。
W3 WorkBuddy诊断练习：workbuddy/practice；只改src/features/practice、docs/reports/practice。Goal：将五类错误明确反馈，改善答题和结果回顾。DoD：至少复用现有五道题语义且答案正确；首次答题评分；重试不刷分；一次提交；失败可重试；reset开始新轮；调用contract回调；独立单测；不写共享记录。详细见WORKBUDDY-PRACTICE.md。
C1 Codex集成与质量：codex/integration；负责共享入口、依赖、合同、物理回归与安卓打包。Goal：接入完成模块并保持现有课程可用。验收：各模块可单独合入，21项原测试加新增必要测试通过、生产构建成功、全站中文/路由/离线资源检查、Android11/15模拟器回归、明确真机范围。可在W任务期间编写适配/回归计划，无需等待全部完成再开始。

WorkBuddy只有一个模型时，先W1再W2再W3，每次独立克隆/分支；有多个并行会话时可各领一个任务。每个模型可先交小而完整PR，不要求三个模块一起交。不要把同一目录交给两个模型，不要并行执行多个模型改AGENTS和lock文件。

## 最终集成的最低门槛
每任务报告含Goal、实际文件、合同版本、截图和实测命令、已知问题、分支、提交SHA和PR链接。仅有截图/方案/骨架不算完成。测试没有执行须写未执行。接口无破坏、无越界、无密钥、无不实教学功能、没有把物理动画变成装饰。
三项任务互不依赖；均依赖已经提交的基线合同和预览，不依赖未来的他人分支。集成时才需要负责人处理接线，避免为了并行而让各模型都改main.tsx。

## 后续可选：远程更新
当前不实施OTA。另建codex/update-delivery，首先明确资源托管地址、更新版本策略、签名/完整性校验、可回退版本与发布责任。缺少托管信息时只写方案和本地可测接口，不编造远端API、不声称可以自动更新旧APK。不把OTA作为W1/W2/W3开工或验收的前置条件。
